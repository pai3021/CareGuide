# 两路候选池与融合策略对照

本轮沿用真实 Qwen Dense + BM25 Top100 分数缓存，比较候选池 20、30、40、60，以及融合方法、权重和 RRF 常数。离线结果支持优先验证原 RRF Top40；尚未将开发集覆盖率当作最终回答效果，也没有替换默认配置。

## 数据与选择规则

- 当前语料 10,015 篇，沿用 [两路实验](rag-score-fusion-dev-20261105.md) 的 1,000 条 dev 和按 gold 文档哈希固定的 500/500 调参与内部验证划分。
- dev 曾参与过开发，本次属于复用开发集的探索，不是新独立测试。冻结 test 不参与调参或此次模型调用。
- 每路候选深度维持 Top100。候选池大小是**送入重排的文档数**，与每路召回深度、最终返回 Top10、RRF 常数是不同参数。
- 对每个固定候选预算独立选择融合配置：RRF 常数 10/30/60，Dense/BM25 权重步长 0.1、和为 1；Min-Max 使用同样权重网格。共 44 个网格项，另保留精确原配置作为对照和稳定平分优先项。
- 只用调参半集的候选覆盖率选择，平分时比较 MRR@10，再优先精确原配置。不用验证半集选权重。
- 实用候选预算优先验证 40；60 作为覆盖与成本敏感性分析。不能因为覆盖随候选数上升，就直接选择最大的候选池。

## 离线结果

下表均为 500 条内部验证样本，尚未重排。

| 候选池 | 原 RRF 4:1 覆盖 | 调参选出方案的覆盖 | 选出方案（Dense:BM25） | 原 RRF 平均候选正文字符 |
| --- | ---: | ---: | --- | ---: |
| 20 | 70.2% | 70.2% | RRF，常数 60，4:1 | 2,702 |
| 30 | 75.8% | 75.8% | Min-Max，0.8:0.2 | 4,013 |
| 40 | 80.0% | 79.0% | RRF，常数 60，0.6:0.4 | 5,322 |
| 60 | 83.0% | 84.0% | RRF，常数 10，0.8:0.2 | 7,917 |

原 RRF Top20 → Top40 增加 49 条金标覆盖，原 Top20 完全保留；正文字符约为原来的 1.97 倍。Top40 → Top60 再增加 15 条覆盖，增加约 49% 正文字符。字符数不是 Token 数，也不是实测费用或延迟。

Top40 的调参配置相较同预算原 RRF 新增覆盖 6 条、丢失 11 条，净减少 5 条。因此本轮没有证据支持用新权重替换原配置。Top60 的调参方案净增 5 条，但不据此跳过成本和最终重排验证。

原排序下，扩大候选池本身不会改变重排前 Top10；最终收益取决于重排器是否能将新增相关文档排入最终 Top10。

完整分区指标、调参网格与配对变化见 [JSON 报告](rag-candidate-pools-dev-20261106.json)。

## 真实重排对照

已固定一个 100 条 query 的开发验证子集，按独立固定种子对验证 query ID 排序抽取，不按命中或漏召回结果挑样本。三组分别为：

1. 原两路 RRF 4:1，候选池 20。
2. 原两路 RRF 4:1，候选池 40，用于隔离扩容作用。
3. 调参半集选出的两路 RRF 0.6:0.4，候选池 40，用于对照同预算融合变化。

三组均使用现有 `Qwen/Qwen3-Reranker-0.6B` 和相同指令、候选正文格式、最终 Top10。每条 query 轮换三组请求顺序，降低固定调用顺序的干扰。每组单独实际请求，不从混合候选一次打分推算不同候选池的输出。

用户已追加授权最多 300 次硅基流动 Rerank 请求；关闭自动重试，每次请求之前持久化预算，响应逐条保存。发送公开 query 和候选正文，不重新请求 Embedding，不调用 LLM、医院工具或冻结 test。

本次对照记录最终 Recall@10、MRR@10、nDCG@10、提供方返回的输入 Token、API 耗时和配对增减。耗时只覆盖独立 Rerank API 调用，不代表完整服务或生产 P95。100 条开发样本属于试验性验证，不替代冻结测试或临床验证。

已完成 300/300 次请求，无失败、无自动重试，三组累计输入 Token 为 1,783,100。以下均为相同 100 条子集上的实际重排结果：

| 方案 | 候选覆盖 | 最终 Recall@10 | MRR@10 | 输入 Token 合计 | API 平均耗时 | API 观测 P95 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 原 RRF 4:1，Top20 | 67.0% | 58.0% | 0.3953 | 358,527 | 0.578 s | 0.617 s |
| 原 RRF 4:1，Top40 | 80.0% | 60.0% | 0.4003 | 710,935 | 0.805 s | 0.870 s |
| 调参 RRF 0.6:0.4，Top40 | 79.0% | 59.0% | 0.3919 | 713,638 | 0.807 s | 0.880 s |

原 RRF Top40 相较 Top20，最终 Top10 新增命中 3 条、丢失 1 条，净增加 2 条。按 query 配对的 2,000 次 bootstrap，Recall@10 差值的 95% 区间为 [-2, +6] 个百分点，不能据此宣称稳定提升。输入 Token 约为 1.98 倍，API 平均耗时约增加 39%。实际金额应按账户账单核对，不从字符数估算费用。

更细的阶段分析：Top40 相较 Top20 新增覆盖 13 条 gold，但其中只有 3 条进入最终 Top10；Top40 内总共有 20 条 gold 被重排留在 Top10 之外。因此候选池扩容存在覆盖收益，但新增候选的相关性排序仍限制最终收益。不能直接把 Top20 → Top40 的 13 个百分点候选覆盖变化当作最终召回提升。

**本轮决定：保留默认 Top20、RRF 常数 60 和 Dense:BM25=4:1。Top40 保留为显式可选配置，不默认支付接近双倍的重排 Token。新融合权重也不启用。** 后续应针对已入池但未进入最终 Top10 的案例，单独评估重排器和候选文本格式；本轮没有验证这些改动，也没有追加模型调用。

聚合结果见 [实际重排报告](rag-pool-rerank-dev-20261106.json)，逐条实际响应见 [公开压缩缓存](../../data/eval/cache/rag-pool-rerank-dev-20261106.json.gz)。缓存包含公开样本/候选 ID、实际返回 ID/分数、Token 和 API 耗时，不含密钥或私人数据。历史冻结测试 Recall@10=66.8% 属于不同样本与配置快照，不与本子集的 58%/60%直接作为前后对比。

## 实现与复现

运行时新增 `CAREGUIDE_RRF_CONSTANT`，默认仍为 60；旧两路和可选通用融合路径使用同一常数。候选池继续通过 `CAREGUIDE_RERANK_CANDIDATES` 配置，最终返回数量保持由调用方 `top_k` 指定。本轮未修改实际私有配置或重启服务。

离线复现（输出必须使用新路径）：

```powershell
python -m scripts.evaluate_rag_candidate_pools `
  --cache data/eval/cache/rag-recall-scores-dev-20261105.json.gz `
  --output tmp/pool-replay/report.json `
  --plan tmp/pool-replay/plan.json

python -m scripts.rerank_rag_candidate_plan `
  --plan tmp/pool-replay/plan.json `
  --report tmp/pool-replay/report.json `
  --cache data/eval/cache/rag-recall-scores-dev-20261105.json.gz
```

第二条默认只验证计划，不加载密钥、不发请求。真实运行另外要求 `--allow-remote-rerank --max-api-requests 300 --config-file <本地私有配置> --output-dir <响应目录>`；已有完整响应可通过相同计划和 `--output-dir` 离线计算结果，不加远端授权参数。

本次实际模型响应也可直接零 API 复算：

```powershell
python -m scripts.rerank_rag_candidate_plan `
  --plan data/eval/cache/rag-pool-rerank-plan-dev-20261106.json `
  --report docs/evaluation/rag-candidate-pools-dev-20261106.json `
  --cache data/eval/cache/rag-recall-scores-dev-20261105.json.gz `
  --response-cache data/eval/cache/rag-pool-rerank-dev-20261106.json.gz
```

报告和计划校验文件原始字节 SHA-256。报告、计划和响应缓存来自同次运行；重新生成计划时请一起使用对应的新报告，不要混用不同序列化的计划哈希。

候选深度/重排边界、两条融合路径的常数一致性、请求预算、响应缓存完整性与原检索回归共 36 项通过。离线网格重放结果一致，Compose 配置校验通过，冻结 test/冻结清单/冻结结果 SHA-256 保持不变。测试夹具仅验证实现，质量结论来自真实分数缓存和实际模型响应。
