# RAG 失败阶段、文本审阅与优化依据

本轮目标是争取提高最终 Recall@10，并形成可核对的优化判断。80% 是探索目标，不是必须通过调整口径兑现的承诺。候选覆盖率、最终检索命中率、回答质量分别报告。

## 可验证的损失分解

复用前轮固定的 100 条开发验证 query 和 300 次实际重排响应，不新增模型请求：

| 两路原 RRF 的处理结果 | Top20 | Top40 |
| --- | ---: | ---: |
| gold 不在两路各 Top100 的并集 | 13 | 13 |
| gold 在召回并集，但被候选池截断 | 20 | 7 |
| gold 已进入候选池，但未进入最终 Top10 | 9 | 20 |
| 最终 Top10 命中 | 58 | 60 |

扩大候选池减少了截断损失，但其中大部分没有转化为最终命中。原融合未重排时 Recall@10=58%、MRR@10=0.3698；Top20 重排后 Recall@10 仍为 58%，MRR@10=0.3953，新命中 3 条同时丢失 3 条。因此不能简单说重排完全无效，它改善了部分首部排序，但命中净收益有限。

可复算的阶段报告见 [JSON](rag-failure-analysis-dev-20261106.json)。

## 80% 目标的上限约束

在同一 100 条样本上，原融合候选覆盖 Top40=80%、Top60=84%、Top100=86%，两路各 Top100 并集=87%。500 条内部验证上，相应值为 80%、83%、86%、88.4%。

- 在 Top40 预算下达到最终 80%，需要把所有已覆盖 gold 都排进 Top10，不能把候选覆盖直接当最终效果。
- 在 Top100 预算下达到最终 80%，也需要将覆盖的 86 条中至少 80 条排进 Top10，保留率约 93%。当前 Top40 的保留率为 60/80=75%。
- 因此，继续调权重或单纯扩池不足以保证 80%；必须验证重排能力，并独立处理真正未召回的 query。

这些是本开发样本的上限分析，不是全量真实业务的质量上限。

## 入池未命中的文本审阅

逐条阅读 Top40 中 20 条“已入池、未进最终 Top10”的 query、标注文档与实际 Top1，以下记录代表性现象。这里只判断文本是否覆盖所问维度，未作医学正确性判断；不修改原 gold，不删除困难 query，不上调原指标。

| query ID | 观察到的文本现象 | 可检验的解释与处理 |
| --- | --- | --- |
| careguide-kuake-14429 | query 明确说“静脉畸形”，实际 Top1 主要说“鸡胸” | 候选实体不一致；应核对疾病实体是否被重排忽略 |
| careguide-kuake-28449 | query 问“非淋”和药物替代，Top1 讲“例假淋漓不尽” | 表面词相近，业务实体不同；适合构造训练阶段的困难负例 |
| careguide-kuake-96803 | query 问“附件炎什么症状”，gold 主要讲治疗和休息，Top1 提到症状 | 单 gold 命中与所问维度可能不一致；需要额外人工相关性标注，原分数仍保留 |
| careguide-kuake-48323 | query 问药物，gold 主要介绍疾病、症状和就诊，Top1 列出治疗药物类别 | 仅凭未命中 gold 不能断言实际候选完全不相关 |
| careguide-kuake-36424 | query 问早期症状和治疗，gold 大量描述社会心理影响，Top1 更直接涉及症状 | 可能存在多个相关段落；补充评测应允许独立多相关标注 |
| careguide-kuake-99527 | query 关心食物是否伤胃，gold 主要讲鼻炎按摩 | 标注文档缺少对明确问题维度的回应；属于标注契约审阅线索 |
| careguide-kuake-27197 | query 在“在月经”处结束，gold 引用了 query 未明确给出的时间事实 | 可见 query 信息不足；不能从缺失上下文推出唯一文档 |
| careguide-kuake-31548 | query 反复引用“图四、图五、图六”，输入没有对应图片 | 文本检索缺失必要的多模态上下文；改写也不能恢复不存在的信息 |
| careguide-kuake-11207 | gold 包含多轮对话分隔符和未显式给出的婴儿上下文 | 候选文本清洗与上下文完整性值得单独验证 |
| careguide-kuake-91373 | query 只有日期、打喷嚏、流鼻涕，竞争段落讨论不同原因 | 输入不足以确定唯一相关段落；需相关性审阅，而不是按 gold 强行推断原因 |

这些案例证明存在值得审查的模式，不证明噪声在整个数据集中的比例，也不把所有失败归因于标注。实体混淆、上下文缺失、单 gold 契约需要分别处理。

## 固定对照与结果

已准备同一批 100 条 query 的三组新增对照，复用实际中文指令、0.6B、Top40 基线：

1. 含义相同的英文指令 + 0.6B + Top40：测试指令因素。
2. 相同英文指令 + 4B + Top40：测试模型容量因素。
3. 相同英文指令 + 4B + Top100：测试更强重排器下的扩池收益。

三组均保持原 RRF 4:1、原 query、原候选正文和最终 Top10。返回完整候选排序，方便定位 gold 的最终位置；不将 gold 用作模型输入。没有筛掉上述文本困难样本。

Qwen 官方建议在多语言场景使用英文指令，见 [官方模型卡](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B)。硅基流动文档列明 Qwen 0.6B/4B/8B 支持 `instruction`，见 [接口文档](https://docs.siliconflow.cn/docs/api/rerank-post)。这些资料提供对照依据，不代表本项目必然获益。

本轮新增对照已在追加授权内完成300次请求。相同英文指令和Top40下，4B将最终Recall@10由60%提高到72%；扩到Top100后为69%。指令单独变化未产生Recall净增。详细质量、Token、耗时、配对区间与可选配置见 [模型对照报告](rag-reranker-models-dev-20261106.md)。冻结 test、语料和历史指标保持不变。

## 面试表述框架

可以围绕“问题—定位—对照—取舍”回答：

> 我没有把混合检索或重排模型的存在当作效果保证。我先记录 gold 在各路候选、融合候选池和最终 Top10 中的位置，把真正漏召回、融合截断和重排损失分开。开发实验中，Top20 扩到 Top40 的候选覆盖提升明显，但最终命中只提高 2 个百分点，重排 Token 接近翻倍，所以没有直接改默认值。随后我逐条审阅失败案例，发现既有实体混淆，也有缺失图片、上下文不足及单 gold 契约问题。因此下一轮固定候选和样本，分别验证指令、模型容量和扩池，并保留原评分与成本记录。

可以继续补充本轮结果：固定样本、相同指令和候选预算，4B相较0.6B新增命中12条、没有丢失原命中；因此提供4B Top40的显式质量优先配置，而不采用更贵且本次效果更差的Top100。当前最终结果是开发子集72%，尚未达到80%。
