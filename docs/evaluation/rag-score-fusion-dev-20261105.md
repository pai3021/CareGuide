# RAG 召回分数融合开发集对照

本轮实测 Dense + BM25 的 Min-Max 加权融合，保留 RRF 默认行为。Min-Max 改善了首部排序，但没有带来稳定的 Recall@10 或重排候选覆盖提升。下一步优先比较候选池容量，再评估增加 BGE-M3 稀疏召回。

## 方法与范围

- 语料为当前 `careguide_kuake_rag_v1`，10,015 条记录，指纹 `6e47b0ad01598a3f1385abb53a9ab7189ca11eb63bd5674a4688e946f4e0f8cf`。
- 使用完整 1,000 条 dev query。按金标文档 ID 和固定种子排序，前 500 条调参、后 500 条内部验证。dev 过去已参与方案选择，这次拆分不构成新的独立测试集。
- Dense 使用 Qwen3-Embedding-0.6B、1024 维和运行时检索指令，查询当前语料的既有索引副本；BM25 使用现有中文 bigram 实现。两路各取 Top100。
- 真实 Embedding 请求共 32 次，批大小 32，SDK 重试关闭，请求前持久化预算。只发送公开 dev query 与检索指令。分数缓存后的网格搜索和诊断完全离线。
- RRF 保留原始排名信息，常数 60；基线 Dense:BM25 = 4:1。
- Min-Max 在每条 query 的每路 Top100 分数内独立归一化，再加权求和；缺失项、恒定分数支路贡献 0。融合分数不是相关性概率。归一化结果受每路候选深度影响。
- 两种融合均在步长 0.1、权重和为 1 的 11 组配置中选择，包含单路消融。选择目标先比较 Top20 金标覆盖率，再比较 MRR@10。内部验证分数不参与选权重。
- 本轮只评估重排前召回/排序。未运行新重排、回答生成或端到端延迟测试；未运行冻结 test，也未更新简历中的冻结测试指标。

## 两路融合结果

以下均为 500 条内部验证样本，重排前指标。

| 方案 | Dense:BM25 | MRR@10 | Recall@10 | 候选覆盖@20 | 候选覆盖@40 |
| --- | --- | ---: | ---: | ---: | ---: |
| Dense 单路 | 1:0 | 0.4316 | 62.2% | 71.2% | 79.6% |
| BM25 单路 | 0:1 | 0.2604 | 39.6% | 44.8% | 51.6% |
| 原 RRF | 4:1 | 0.4123 | 64.2% | 70.2% | 80.0% |
| 调参 RRF | 0.8:0.2 | 0.4123 | 64.2% | 70.2% | 80.0% |
| 调参 Min-Max | 0.7:0.3 | 0.4384 | 63.2% | 70.6% | 79.2% |

RRF 选出的 0.8:0.2 与原 4:1 比例相同。Min-Max 的 Top20 覆盖比基线多 2 条：新增覆盖 5 条，同时丢失 3 条；Top10 新增 2 条、丢失 7 条。仅凭这次结果不替换默认 RRF，也不能宣称召回显著提升。

完整 1,000 条 dev 上，原 RRF 与所选 Min-Max 的 Top20 覆盖分别为 72.8%、72.9%；这些全 dev 数字包含调参样本，只用于描述。

## 阶段诊断与候选池

500 条内部验证样本中，Dense Top100 金标覆盖 86.0%，BM25 Top100 为 57.6%，两路并集为 88.4%。原 RRF 压缩至 Top20 后只覆盖 351 条：

- 58 条：金标未进入任一路 Top100，单纯更换融合无法召回。
- 91 条：金标已在两路并集中，但未进入融合 Top20。
- 351 条：金标已进入重排候选池。

因此，149 条 Top20 漏召回中有 91 条发生在融合截断阶段。直接将 RRF 候选池从 20 扩到 40，内部验证候选覆盖由 70.2% 到 80.0%，完整 dev 由 72.8% 到 81.2%。这只是更多候选进入重排的上限收益，尚未测量新增重排成本与最终 Recall@10。

逐条诊断还发现：Dense 权重 4、BM25 权重 1 时，Dense 第 100 名的 RRF 分数为 `4/(60+100)=0.025`，仍高于 BM25 独有第 1 名的 `1/(60+1)≈0.0164`。因此，BM25 独有的高位候选也可能完全进不了 Top20。

另做一个探索性候选保底对照：保留原 RRF Top20，追加 BM25 Top3 中遗漏的项，总数最多 23，随后应统一交给重排。该假设是在本轮 dev 诊断后提出，以下仅作开发集探索。

| 候选策略 | 完整 dev 覆盖 | 内部验证覆盖 | 平均候选数（完整 dev） |
| --- | ---: | ---: | ---: |
| 原 RRF Top20 | 72.8% | 70.2% | 20 |
| Top20 + 遗漏的 BM25 Top3 | 73.7% | 71.0% | 21.536 |
| RRF 按每条 query 相同实际候选数量截断 | 73.3% | 71.0% | 21.536 |
| RRF Top23 | 74.1% | 72.0% | 23 |

保底方案没有在内部验证上胜过相同实际候选数量的 RRF；不能把扩容带来的提升全部归因于候选多样性。暂不加入运行时默认链路。

## BGE-M3 第三路的状态

本节记录 2026-11-05 的实验边界。后续已完成的真实 BGE-M3 稀疏召回对照见 [2026-11-06 报告](rag-bge-sparse-dev-20261106.md)。

已准备稀疏倒排点积索引和本地 `BGEM3FlagModel` 编码入口，供 Dense/BM25/BGE sparse 三路实验使用。本轮环境没有 BGE-M3 权重和 FlagEmbedding，**没有实测第三路，也没有三路收益结论**。稀疏索引的算法回归使用人工权重，仅验证计算与范围过滤，不作为相关性质量证据。

[BGE 官方文档](https://bge-model.com/bge/bge_m3.html)说明，BGE-M3 sparse 输出模型生成的 token 权重，通过 query/document 共享 token 的权重乘积求和；它与现有基于词频统计的 BM25 是不同检索信号。后续需准备版本固定的真实权重，生成文档与 query 的 sparse 编码，再沿用相同调参协议比较第三路的独立增益和本地推理成本。

## 离线复现

已保存的压缩缓存只含公开样本 ID、金标 ID、候选 ID 和原始分数；不含密钥、query 向量或私人数据。缓存属于 2026-11-05 的实测快照。

```powershell
python -m scripts.evaluate_rag_score_fusion `
  --cache data/eval/cache/rag-recall-scores-dev-20261105.json.gz `
  --output tmp/rag-fusion-replay.json `
  --diagnostics tmp/rag-fusion-gold-ranks.jsonl
```

该命令不加载任何私有配置，不发 API 请求，只读取 dev、语料与分数缓存。报告记录缓存 SHA-256、语料指纹、dev SHA-256、选权重目标和每个方案的三组指标。逐条诊断保存各阶段金标排名。

重新采集需自行准备与语料指纹匹配的独立 Chroma 副本，并显式授权真实 Embedding 请求；脚本没有冻结 test 参数。仅缓存 query 向量不会重建文档索引。

```powershell
python -m scripts.cache_rag_recall_scores `
  --output tmp/new-rag-scores/scores.json `
  --chroma-copy <独立索引副本目录> `
  --config-file <本地私有配置路径> `
  --allow-remote-embeddings --max-api-requests 32
```

不加远端授权参数时不会发 Embedding 请求；未指定 Chroma 副本时只采集 BM25。已具备本地 BGE-M3 权重及依赖时，可附加 `--local-bge-model <本地目录>`，该入口强制模型离线加载，截断长度 512，CPU 编码。三路完整网格共 66 组；其模型版本、截断影响和实际收益仍需另行验证。

算法、范围过滤、候选保底、请求预算及已有语料完整性回归共 16 项通过。生产运行时和默认融合配置未改动。机器可读结果见 [JSON 报告](rag-score-fusion-dev-20261105.json)。
